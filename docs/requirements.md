## 1. はじめに

### 1.1 この文書の目的

「対戦表メーカー」の開発を依頼するにあたり、**作るものの範囲と挙動を、実装者が判断に迷わない粒度で確定させる**ことを目的とする。

### 1.2 想定読者

本アプリを実装する開発者。特定の業務知識やスポーツ大会運営の経験は前提としない。

### 1.3 この文書で決めること／決めないこと

| 決めること | 決めないこと |
|---|---|
| 何を作り、何を作らないか（5章） | 画面の配色やレイアウトの詳細 |
| 各機能の挙動と判断ルール（6章） | 使用するフレームワークやライブラリ |
| 満たすべき品質の水準（7章） | 開発の進め方、スケジュール |

技術選定は実装者に委ねる。ただし7章に挙げる制約（サーバーを持たないこと等）は満たすこと。

### 1.4 用語

| 用語 | 意味 |
|---|---|
| 大会 | 1回分の対戦のまとまり。参加者・形式・勝敗記録の一式を指す |
| 対戦表 | 大会の組み合わせと結果を表した図または表 |
| トーナメント | 負けたら終わりの勝ち抜き形式 |
| リーグ | 全員が総当たりする形式 |
| 不戦勝（シード） | 対戦相手がおらず、戦わずに次のラウンドへ進むこと |
| 作成者 | 大会を作り、勝敗を入力する人。いわゆる幹事役 |
| 閲覧者 | 共有URLを開いて対戦表を見るだけの人 |
| 勝点 | リーグで順位を決めるための点数。勝ち3・引き分け1・負け0 |
| 得失点差 | 総得点から総失点を引いた値 |

## 2. 背景と課題

### 2.1 現状

集まりや遊びの場で、その場の思いつきで対戦を始めることがある。このとき対戦表は作らず、**組み合わせと勝敗を作成者が頭で記憶している**。

### 2.2 課題

| # | 課題 | 起きること |
|---|---|---|
| 1 | 記憶に頼っている | 勝敗の食い違いが起きる。「さっき勝ったのはどっちだったか」で揉める |
| 2 | 次の対戦が共有されていない | 次に誰と誰がやるのかを毎回口頭で確認することになり、その都度止まる |
| 3 | 全員が同じものを見られない | 情報が作成者の頭の中にしかなく、参加者は自分の番が来るまで状況が分からない |

課題1は**信頼性**の問題、課題2は**進行の速さ**の問題、課題3は**共有**の問題であり、いずれも「頭で記憶している」ことに起因する。

### 2.3 既存サービスとの比較

当初「大会運営サービスは登録が必要で手順が重い」と想定していたが、調査の結果**この想定は誤りだった**。登録不要で使えるサービスが複数存在する。

| サービス | 登録 | 対応形式 | 勝敗の記録 | 共有 |
|---|---|---|---|---|
| [大会運営.net](https://taikaiunei.net/) | 不要 | トーナメント（4〜128人） | 可（スコア・取り消し） | **閲覧専用URL・リアルタイム更新** |
| [トーナメントクリエイター](https://tournament-creators.com/) | **必要** | トーナメント | 可 | 公開ページ |
| [まめわざ](https://mamewaza.com/tools/tournament.html) | 不要 | トーナメント／リーグ（別ツール） | 表の作成が中心 | — |
| [ENIBLO なんでもリーグ作成](https://www.eniblo.org/ja/apps/all_leagues) | 不要 | リーグ | 可 | 順位表の共有 |

特に**大会運営.net は本書の要件の大半を既に満たしている**。共有についても、本書が採用したスナップショット方式（8.1-2）より優れたリアルタイム更新を提供している。

調査した範囲で既存サービスが満たしていないのは次の2点のみである。

1. **トーナメントとリーグを1つのアプリで扱えること** — 上表のとおり、どのサービスも片方しか扱えない。形式が変わるたびに別のツールを覚え直す必要がある
2. **自分たちの使い方に合わせて手を入れられること** — 不戦勝の人数の指定など、細かい挙動を自分で決められる

> **本書は「上記2点のために自作する」という前提で書かれている。** 既存サービスで足りると判断した場合、開発そのものを見送る選択もあり得る（8.4-1）。

## 3. 利用者と利用シーン

### 3.1 利用者

| 区分 | 誰か | することは |
|---|---|---|
| 主 | **作成者**（幹事役） | 参加者を入力し、対戦表を作り、勝敗を記録する |
| 副 | **閲覧者**（参加者・その場にいる人） | 対戦表を見る。入力はしない |

特別なITスキルは前提としない。**説明書を読まずに使えること**を条件とする。

### 3.2 利用シーン

1. **その場で始める** — 集まりの最中に「トーナメントやろう」となる。作成者が自分の端末で参加者名を入れ、対戦表を出す。準備に時間をかけない
2. **試合ごとに記録する** — 1試合終わるたびに、その場にいる誰かが端末を操作して勝った側をタップする
3. **みんなで見る** — 端末の画面を見せる。あるいは共有URLを送り、各自の端末で見てもらう

### 3.3 利用環境

- 端末は**スマートフォンが中心**。PCから使うこともある
- 屋内外を問わず、通信状況が良くない場所でも使う可能性がある
- 参加者は**4〜16名程度、典型は10名**

## 4. ゴールと成功の定義

### 4.1 ゴール

**対戦の組み合わせと勝敗を、頭で記憶する必要をなくす。** その場にいる全員が同じ対戦表を見られる状態にする。

### 4.2 成功の定義

次をすべて満たせば成功とみなす。

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | 10名の対戦表を**60秒以内**に作れる | 名前入力から表の表示までを実測する |
| 2 | 初めて触る人が**説明なしで**勝敗を記録できる | その場の参加者に端末を渡して観察する |
| 3 | 画面を見れば**次にやる試合が分かる** | 参加者に「次は誰と誰か」を聞いて即答できるか確認する |
| 4 | 勝敗の食い違いによる言い争いが起きない | 使用後に作成者に確認する |
| 5 | 実際の集まりで**2回以上使われる** | 使用回数を追う |

条件5は「一度作って終わり」を避けるための指標であり、実用に耐えるかどうかの最終判断とする。

### 4.3 ゴールとしないこと

- 公式競技会の運営に耐える正確性・証跡の保全
- 過去の大会成績の蓄積や分析
- 参加者間のコミュニケーション（チャット、通知など）

## 5. スコープ

### 5.1 初回リリースに含むもの

| 分類 | 内容 |
|---|---|
| 形式 | トーナメント、リーグ（総当たり） |
| 大会の作成 | 大会名、参加者の追加・一括登録・編集・並べ替え、抽選 |
| トーナメント設定 | 不戦勝の人数、3位決定戦の有無 |
| 記録 | 勝敗、得点、引き分け（リーグのみ）、取り消し、一括リセット |
| 表示 | トーナメント図、星取表、次にやる試合の強調、拡大縮小 |
| 結果 | 優勝・準優勝・第3位、戦績一覧、リーグ順位表 |
| 共有・保存 | 閲覧専用の共有URL、ブラウザ内への自動保存 |

詳細は6章の機能一覧（F-01〜F-23）を参照。

### 5.2 初回リリースに含まないもの（将来対応）

| 内容 | 見送る理由 |
|---|---|
| 印刷・PDF出力 | 紙に出す想定が今はないため |
| 過去の大会の履歴 | 1回ごとに使い切る運用で足りるため |
| 画像として保存 | 共有URLで代替できるため |
| リーグの消化順の提示 | 10名程度ならその場で決める方が速いため |
| 端末をまたいだ同期・リアルタイム更新 | サーバーが必要になり、規模に見合わないため |
| アカウント／ログイン | 手軽さを損なうため。作成者本人が明確に不要と判断済み |
| チーム戦（メンバー管理）、複数日程、予選リーグ＋決勝トーナメント | 想定する使い方の範囲外のため |
| ダブルエリミネーション等の複雑な形式 | 同上 |

### 5.3 スコープに関する判断基準

迷った場合は次の順で判断する。

1. **その場で数分以内に使い始められるか** — 手順が増える機能は入れない
2. **説明なしで分かるか** — 設定項目が増える機能は慎重に扱う
3. **サーバーなしで実現できるか** — 実現できないものは将来対応に回す

## 6. 機能要件

### 6.1 画面構成

3つの画面で構成する。スマートフォンでは1画面ずつ切り替え、PCなど横幅の広い端末では「設定」と「対戦表」を左右に並べて表示する。

| 画面 | 役割 | 入力 |
|---|---|---|
| 設定画面 | 大会名・参加者・形式の設定 | 可 |
| 対戦表画面 | 対戦表の閲覧と勝敗の記録 | 可 |
| 閲覧画面 | 共有URLを開いた人が見る画面 | **不可**（閲覧専用） |

### 6.2 機能一覧

| ID | 機能 | 対象形式 |
|---|---|---|
| F-01 | 大会名を設定する | 共通 |
| F-02 | 参加者を1人ずつ追加する | 共通 |
| F-03 | 参加者名をまとめて貼り付けて一括登録する | 共通 |
| F-04 | 参加者を修正・削除・並べ替えする | 共通 |
| F-05 | 組み合わせを抽選する | 共通 |
| F-06 | 形式（トーナメント／リーグ）を選ぶ | 共通 |
| F-07 | 不戦勝の人数を選ぶ | トーナメント |
| F-08 | 3位決定戦の有無を選ぶ | トーナメント |
| F-09 | トーナメント表を表示する | トーナメント |
| F-10 | 星取表を表示する | リーグ |
| F-11 | 次にやる試合を目立たせる | 共通 |
| F-12 | 表を拡大縮小する | 共通 |
| F-13 | 勝者を記録する | 共通 |
| F-14 | 記録を取り消す | 共通 |
| F-15 | 得点を記録する | 共通 |
| F-16 | 引き分けを記録する | **リーグのみ** |
| F-17 | 勝敗をすべてリセットする | 共通 |
| F-18 | 優勝・準優勝・第3位を表示する | トーナメント |
| F-19 | 各参加者の戦績を一覧表示する | 共通 |
| F-20 | 順位表を表示する | リーグ |
| F-21 | 閲覧専用の共有URLを発行する | 共通 |
| F-22 | 自動保存し、次回開いたときに再開する | 共通 |
| F-23 | 大会を新規作成する（現在の内容を破棄） | 共通 |

### 6.3 大会の準備（F-01〜F-08）

- **F-01** 大会名は任意入力とし、未入力でも対戦表を作成できる。未入力時は表の見出しを空欄にする。
- **F-02** 参加者名を入力して追加する。空文字は追加しない。同名の参加者を許可する（実在の集まりでは「たなか」が2人いる場合があるため）。
- **F-03** 改行またはカンマ区切りのテキストを貼り付けて一括登録する。既存の参加者は置き換える。
- **F-04** 参加者は名前の修正、削除、1つずつの上下移動ができる。**参加者リストの並び順が、そのまま対戦表の配置順になる。**
- **F-05** 抽選は参加者リストの順序をランダムに入れ替える。抽選を実行すると記録済みの勝敗はすべて破棄する（組み合わせが変わり、記録の意味が失われるため）。実行前に確認する。
- **F-06** 形式はトーナメントとリーグから選ぶ。既定はトーナメント。形式を切り替えると記録済みの勝敗は破棄する。実行前に確認する。
- **F-07** 不戦勝（1回戦を戦わずに通過する人）の人数を作成者が選ぶ。詳細は 6.6.1。
- **F-08** 3位決定戦を行うかどうかを選ぶ。既定は行う。詳細は 6.6.2。

### 6.4 対戦表の表示（F-09〜F-12）

- **F-09** トーナメント表は左から右へ進行し、勝ち上がりを線でつなぐ。各試合は2人の名前を上下に並べたカードで表す。不戦勝の枠は「シード」または「不戦勝」と明示する。
- **F-10** リーグは縦横に参加者を並べた星取表で表す。各セルには自分から見た結果（○／●／△）を表示し、得点が入力されている場合は併記する。自分同士のセルは斜線などで潰す。
- **F-11** まだ結果が入っていない試合のうち、**いま実施できるもの**（トーナメントでは両者が確定している試合、リーグでは全未消化試合）を視覚的に区別する。「次に誰と誰がやるのか分からない」という課題への直接の回答であり、必須とする。
- **F-12** 参加者が多い場合に全体を見渡せるよう、表示倍率を変更できる。横に収まらない場合は横スクロールを許容するが、**ページ全体が横スクロールしてはならない**（表の領域内でのみスクロールする）。

### 6.5 勝敗の記録（F-13〜F-17）

- **F-13** 勝者を記録する。操作方法は形式ごとに異なる。
  - **トーナメント**：対戦カード上の**勝った側の名前**をタップする
  - **リーグ**：星取表の**セルをタップ**して記録欄を開き、そこで結果（勝ち／負け／引き分け）と得点を選ぶ。**対称位置のセル（相手から見た結果）は自動的に反転して埋める**
  - いずれもログインや権限の区別は行わず、画面を操作できる人は誰でも記録できる
- **F-14** 記録を取り消す。トーナメントでは記録済みの勝者をもう一度タップする。リーグでは記録欄から「未記録に戻す」を選ぶ。トーナメントで取り消した場合、**その試合より先の試合の記録は自動的に破棄する**（勝ち上がる人が変わり、記録の意味が失われるため）。
- **F-15** 各試合に両者の得点を数値で記録できる。得点は任意入力とし、未入力でも勝敗は記録できる。0以上の整数のみを受け付ける。
- **F-16** 引き分けはリーグでのみ、F-13 の記録欄から選べる。トーナメントでは勝ち上がる人が決まらないため選択肢に出さない。
- **F-17** 参加者や設定は残したまま、記録済みの勝敗だけをすべて消せる。実行前に確認する。

### 6.6 トーナメントのルール

#### 6.6.1 組み合わせの作り方

参加者を上から2人ずつ組み合わせる。人数が2の累乗でない場合、余った人は**不戦勝**としてそのラウンドを戦わずに通過する。

1. 1回戦の不戦勝の人数は作成者が選ぶ。選べるのは **参加人数と同じ偶奇で、0以上・参加人数−2以下** の値に限る（残りが2人ずつ組めなくなるため）。11名なら 1／3／5／7／9名。
2. 既定値は選べる中で**最も少ない人数**とする。10人程度の集まりでは、全員が早く試合に出られる方が待ち時間が減るため。
3. 不戦勝になるのは**参加者リストの下位**の人とする。誰をシードにするかは並べ替えで指定できる。
4. 不戦勝の枠は1回戦の列に均等に散らして配置する（シード同士が早い段階で当たり続けるのを避けるため）。
5. 2回戦以降は、その時点で残っている人数が奇数のときだけ1名が不戦勝で通過する。
6. 不戦勝は「勝ち数」に数えない。
7. 上記の結果、**総試合数は必ず「参加人数 − 1」**になる。実装の検算に使える。

参加人数と同じ偶奇の値を選ばせるため、**参加人数が変わったときは選択値を有効な値に丸める**。

#### 6.6.2 3位決定戦

準決勝（決勝に上がる2つの枠）が**どちらも対戦**である場合にのみ、その敗者同士の試合として3位決定戦を組む。

片方が不戦勝で決勝に上がる形（例：6名）では準決勝の敗者が1人しかいないため、**試合は組まず、その1人を第3位として扱う**。この挙動は「3位決定戦を行う」設定に関わらず適用する。

### 6.7 リーグのルール

1. 全員が1回ずつ総当たりする。総試合数は `参加人数 ×（参加人数 − 1）÷ 2`。
2. 勝点は **勝ち3・引き分け1・負け0** とする（既定値）。
3. 順位は次の順に比較して決める。
   1. 勝点の多い順
   2. 得失点差の大きい順
   3. 総得点の多い順
   4. それでも並ぶ場合は**同順位として並べて表示**する（アプリでは決めきらず、その場の人が決める）
4. **得失点差と総得点は、両者の得点が入力されている試合のみを集計対象とする。** 得点を入れずに勝敗だけ記録した試合は0対0として扱わない。
5. 得点を1試合も入力しない運用では、勝点が並んだ時点で同順位になる。これは許容する。

### 6.8 結果の表示（F-18〜F-20）

- **F-18** トーナメントでは優勝・準優勝・第3位を表示する。未確定の箇所は空欄と分かる形で表示する。
- **F-19** トーナメントでは、参加者ごとの勝ち数・負け数と現在の状況（「優勝」「準決勝敗退」「出場中」など）を一覧表示する。
- **F-20** リーグでは 6.7 の規則に従った順位表を表示する。列は「順位・参加者・勝点・勝／分／敗・得点・失点・得失点差」とする。**リーグでは F-19 の内容を本表に含めるものとし、別途の戦績一覧は設けない。**

### 6.9 共有と保存（F-21〜F-23）

- **F-21** 現在の対戦表の内容をすべて含んだURLを発行し、クリップボードにコピーする。**このURLを開いた人は閲覧のみ可能**とし、勝敗の記録や設定変更はできない。誤って手元だけを書き換え、幹事の画面と食い違う事故を防ぐため。
- **F-21 の制約** 共有URLは**発行した時点の内容**を保持する。試合が進んだ場合は、URLを発行し直して共有する必要がある。閲覧画面には「この表は共有された時点のものです」と明示する。
- **F-22** 入力内容は自動的に保存し、同じ端末の同じブラウザで開き直したときに続きから再開する。保存はブラウザ内に限り、サーバーには送信しない。
- **F-23** 現在の内容を破棄して新しい大会を始められる。実行前に確認する。

### 6.10 境界・異常系

| 状況 | 挙動 |
|---|---|
| 参加者が0〜1名 | 対戦表を表示せず、「2名以上追加してください」と案内する |
| 参加者が33名以上 | 動作保証の対象外（7章の想定規模を参照）。入力自体は拒否しない |
| 同名の参加者がいる | 許可する。区別はリスト上の並び順で行う |
| 参加者名が長い | 表の中では省略表示する（全体は設定画面で確認できる） |
| 記録済みの勝敗を変更した | その試合より先の記録を自動的に破棄する |
| 参加者を追加・削除した | 成立しなくなった記録のみ破棄し、残せる記録は保持する |
| 保存領域が使えない（プライベートモード等） | 保存に失敗してもアプリは動作を継続する。再開できない旨は特に警告しない |
| 壊れた共有URLを開いた | 空の状態で起動し、エラーで停止しない |

## 7. 非機能要件

### 7.1 対応環境

| 区分 | 対象 |
|---|---|
| スマートフォン | iOS Safari、Android Chrome の最新2バージョン |
| PC | Chrome、Edge、Safari、Firefox の最新2バージョン |
| 画面幅 | **320px から** 操作が完結すること |

スマートフォンの縦持ちを第一に設計する。PCは横幅を活かして設定と対戦表を並べて表示する。

### 7.2 想定規模

- 参加者 **2〜32名** を動作保証の範囲とする（典型は10名）
- 32名の場合、リーグの試合数は496件になる。この規模でも 7.3 の性能条件を満たすこと

### 7.3 性能

| 項目 | 条件 |
|---|---|
| 初回表示 | 1秒以内（通信環境が良好な場合） |
| 勝敗の記録から画面反映まで | 体感で待ちが生じないこと（目安100ミリ秒以内） |
| 参加者32名での表の再描画 | 同上 |

### 7.4 オフライン動作

一度読み込んだあとは、**通信が切れても対戦表の作成・記録・閲覧ができること**。屋外や電波の弱い場所で使う可能性があるため。

共有URLの発行はオフラインでも可能とする（送信は利用者が別の手段で行う）。

### 7.5 データの扱い

- 保存先は**利用者のブラウザ内のみ**とし、サーバーへは一切送信しない
- 扱う個人情報は**参加者名のみ**。作成者が入力した文字列をそのまま保持する
- 共有URLには参加者名を含む対戦表の内容がすべて入る。**URLを知っている人は誰でも閲覧できる**ことを、共有操作時に利用者へ明示すること
- アクセス解析や広告のための第三者への送信は行わない

### 7.6 セキュリティ

- 認証・権限管理は行わない。画面を操作できる人は誰でも記録できる（6.5 F-13）
- 秘匿性の高い情報は扱わない前提とし、共有URLの推測困難性以上の保護は求めない

### 7.7 使いやすさ

| 項目 | 条件 |
|---|---|
| タップ領域 | 44×44px 以上 |
| 色への依存 | 勝敗を**色だけで表現しない**。記号（✔／取り消し線、○／●／△）を併用する |
| 文字サイズ | 参加者名は本文相当のサイズを確保し、拡大しなくても読めること |
| 誤操作からの復帰 | 記録の取り消しができること（F-14）。破壊的な操作は実行前に確認すること |

### 7.8 公開と運用

- **静的ファイルのみで動作する構成**とし、無料の静的ホスティング（GitHub Pages 等）で公開できること
- サーバーの運用・監視・バックアップを必要としないこと
- 誰でもURLを開くだけで利用できること（インストール、登録を不要とする）

### 7.9 保守性

- 依存ライブラリは最小限にとどめる。長期間放置しても壊れにくいことを優先する
- ビルド作業なしで動作する構成が望ましい（必須ではない）
- 6.6・6.7 の計算規則は自動テストで検証できる形にすること。特に「総試合数＝参加人数−1」「リーグの試合数＝n(n−1)/2」は検算に使える

## 8. 制約・前提と未決事項

### 8.1 制約

サーバーを持たない構成を選んだことにより、次の制約を受け入れる。

| # | 制約 | 影響 |
|---|---|---|
| 1 | 端末をまたいだ同期ができない | 作成者が使った端末以外では続きを開けない |
| 2 | 共有URLは発行時点のスナップショット | 試合が進むたびに送り直す必要がある |
| 3 | 保存はブラウザ内のみ | ブラウザのデータを消すと大会も消える。プライベートモードでは再開できない |
| 4 | 権限管理がない | 端末を渡した相手が誤って記録を消せる。取り消し機能で緩和する |
| 5 | 共有URLが長くなる | 参加者が多いとURLが数千文字になる。短縮にはサーバーが要るため受け入れる。**32名のリーグなど大規模な場合、URLが長すぎて一部のアプリやブラウザで開けない可能性がある**。10名程度の想定規模では問題にならない |

### 8.2 前提

- 入力は**1台の端末**で行い、必要に応じてその端末を回す
- 参加者は10名程度。32名を超える大会には使わない
- 対戦相手の組み合わせは**参加者リストの並び順**で決まる。作成者がこれを理解して並べ替える

### 8.3 決定の記録

検討の過程で判断が分かれた点と、採用した結論を残す。

| # | 論点 | 結論 | 理由 |
|---|---|---|---|
| 1 | 見せ方 | 共有URLを送り各自の端末で見る | 全員が同じ表を見られる。サーバー不要で実現できる |
| 2 | 共有URLを開いた人の権限 | **閲覧のみ** | 手元だけ書き換わり作成者の画面と食い違う事故を防ぐ |
| 3 | 入力する人 | 1台を回して誰でも | 権限管理を持たずに済み、その場の運用に合う |
| 4 | リーグの同勝点 | **得失点差**で決める | 直接対決より計算が単純で、3者以上が並んでも決まる |
| 5 | 引き分け | **リーグのみ**認める | トーナメントでは勝ち上がる人が決まらない |
| 6 | 不戦勝の人数 | **作成者が毎回選ぶ** | 集まりの性格によって望ましい形が変わるため |
| 7 | 勝点の配分 | 勝3・分1・敗0 | 一般的なサッカー式に合わせた |
| 8 | リーグの「次の試合」 | 未消化のセルを目立たせるのみ | 消化順の提示は10名規模では過剰 |
| 9 | アプリ名 | 対戦表メーカー | トーナメントとリーグの両方を扱うため「トーナメント表」としない |
| 10 | 公開先 | GitHub Pages（`oshima0627/tournament`） | 静的ファイルのみで動き、無料で公開できる |
| 11 | 33名以上を入力したとき | 警告を表示したうえで動作させる | 想定外の使い方を禁止するより、自己責任で使えた方がよい |
| 12 | 将来対応の実施順 | 印刷 → 画像保存 → 履歴 → リーグの消化順提示 | 実装コストが小さく効果が確実なものから |

### 8.4 未決事項

| # | 未決事項 | 決める人 | 期限の目安 |
|---|---|---|---|
